# Сервис объявлений

Приложение для публикации, поиска и просмотра частных объявлений
о продаже товаров и услуг. Консольная версия (ПР1–ПР3) дополнена
веб-интерфейсом на Django (ПР5).

## Назначение
Позволяет пользователям размещать объявления, находить чужие
объявления по названию и категории, отслеживать статус своих
объявлений и снимать их с публикации.

## Используемые технологии
- Python 3;
- Django 5.2 — веб-фреймворк;
- HTML — разметка веб-страниц;
- CSS и Bootstrap 5.3 — оформление страниц;
- pytest — автоматизированные тесты;
- flake8 — проверка качества кода.

## Целевая аудитория
Частные лица, желающие быстро продать/купить товар или
предложить услугу без посредников.

## Предметная область
Онлайн-платформа объявлений: каждый пользователь может
публиковать объявления, относящиеся к определённой категории,
просматривать и фильтровать объявления других пользователей.
Объявление показывается 30 дней с даты публикации, после чего
его срок размещения истекает; продавец может снять объявление
с публикации раньше.

## Основные сущности
- Пользователь (user) — имя автора объявления
- Объявление (ad) — id, название, категория, цена, автор,
  дата публикации, статус
- Категория (category) — тематическая группа объявления

## Объектная модель
Начиная с ПР3 сущности предметной области представлены классами
(модуль `ads.py`), а данные — объектами этих классов.

| Класс      | Атрибуты | Методы |
|------------|----------|--------|
| `User`     | `name` | `__init__`, `__str__`, `has_name()` — сравнение имени без учёта регистра |
| `Category` | `name` | `__init__`, `__str__`, `has_name()` — сравнение названия без учёта регистра |
| `Ad`       | `id`, `title`, `category: Category`, `price`, `seller: User`, `publish_date`, `is_active`; константа `MAX_ACTIVE_DAYS = 30` | `__init__` (с проверкой данных), `__str__`, свойство `status`, `get_status()`, `is_expired()`, `deactivate()`, `matches_title()`, `belongs_to()`, `is_sold_by()`, `to_dict()`, `from_dict()` |

### Взаимодействие объектов
- объявление `Ad` содержит ссылки на объекты `Category` и `User`;
- `Ad.belongs_to()` делегирует проверку объекту `Category`,
  а `Ad.is_sold_by()` — объекту `User` (метод `has_name()`);
- `Ad.__str__()` использует строковые представления категории
  и продавца;
- `Ad.to_dict()` / `Ad.from_dict()` преобразуют объект в словарь
  для JSON и обратно, создавая вложенные объекты `User` и `Category`.

### Что осталось обычными функциями
Операции над коллекцией объявлений (`add_ad`, `find_ads`,
`filter_ads_by_category`, `find_ads_by_seller`, `filter_ads_by_price`,
`sort_ads_by_price`, `find_ad_by_id`, `deactivate_ad`,
`get_category_names`, `get_stats`), работа с файлами (`storage.py`)
и безопасный ввод (`utils.py`) не относятся к отдельному объекту,
поэтому остались функциями. Коллекции работают со списком объектов
`list[Ad]`.

Некорректные данные (пустое имя, отрицательная цена, неверный id)
отклоняются конструкторами с исключением `ValueError`; меню
перехватывает его и выводит сообщение об ошибке.

## Веб-интерфейс (ПР5)

### Django-проект и приложения
| Пакет | Назначение |
|-------|------------|
| `adservice/` | конфигурация Django-проекта: `settings.py`, корневой `urls.py`, `asgi.py`, `wsgi.py` |
| `homepage` | главная страница, общий HTML-каркас `page()`, обработчик ошибки 404, CSS проекта |
| `listings` | объявления: список и страница отдельного объявления (имя `ads` занято модулем `ads.py` с классами) |
| `categories` | категории: список категорий и объявления выбранной категории |

Отдельное приложение для пользователей не создавалось: в Django уже
есть встроенная модель `User` (`django.contrib.auth`), работа с ней
появится вместе с регистрацией и авторизацией.

### Страницы и URL
| URL | View-функция | Что показывает |
|-----|--------------|----------------|
| `/` | `homepage.views.index` | описание сервиса, статистика (`get_stats`), ссылки на разделы |
| `/ads/` | `listings.views.ads` | все объявления с ценой, категорией, продавцом и статусом |
| `/ads/?sort=price`, `/ads/?sort=-price` | `listings.views.ads` | сортировка по цене (`sort_ads_by_price`) |
| `/ads/<int:ad_id>/` | `listings.views.ad_detail` | карточка объявления (`find_ad_by_id`), ссылка на категорию |
| `/categories/` | `categories.views.categories` | категории (`get_category_names`) и число объявлений в каждой |
| `/categories/<str:category_name>/` | `categories.views.category_detail` | объявления категории (`filter_ads_by_category`) |

Если объявление или категория не найдены, страница возвращает код 404.
Для любых других несуществующих адресов в корневом `urls.py`
подключён обработчик `handler404 = "homepage.views.page_not_found"`
(собственная страница видна при `DEBUG = False`).

### Как устроены страницы
- view-функции загружают объявления из `data/ads.json` средствами
  ПР3 (`storage.load_ads`) и используют функции и методы объектов
  `Ad`, не дублируя предметную логику;
- HTML формируется функцией `page()` из `homepage/views.py`:
  она задаёт общий каркас (кодировка, viewport, Bootstrap 5.3 через
  CDN, навигация, подвал);
- ссылки строятся по именам маршрутов через `reverse()`;
- текст из данных (названия, имена) экранируется `escape()`;
- собственные стили — `homepage/static/homepage/css/style.css`;
- статус объявления выводится цветным бейджем: активно — зелёный,
  срок истёк — жёлтый, снято с публикации — серый.

### Отложено до следующих работ
Добавление и снятие объявлений, поиск по названию и по продавцу
работают в консольной версии; в веб-интерфейсе они появятся вместе
с формами и POST-запросами. Переход с JSON на базу данных — после
изучения Django ORM.

## Возможности консольной версии
- просмотр всех объявлений;
- поиск объявлений по подстроке в названии;
- фильтрация объявлений по категории;
- сортировка объявлений по цене;
- просмотр объявлений конкретного продавца;
- добавление нового объявления;
- снятие объявления с публикации;
- статистика: количество и средняя цена активных объявлений;
- автоматическое определение статуса объявления (активно /
  снято с публикации / срок истёк) на основе даты публикации;
- данные сохраняются между запусками в JSON-файле.

## Формат хранения данных
Объявления хранятся в `data/ads.json` в виде списка словарей.
При загрузке каждый словарь превращается в объект `Ad`
(`Ad.from_dict`), при сохранении — обратно в словарь (`Ad.to_dict`).
Некорректные записи пропускаются с сообщением, ошибки записи файла
не приводят к аварийному завершению программы. Путь к файлу для
веб-версии задан в настройке `ADS_DATA_FILE`.
```json
{
  "id": 1,
  "title": "Продам горный велосипед",
  "category": "Транспорт",
  "price": 15000,
  "seller_name": "Иван Петров",
  "publish_date": "2026-09-01",
  "is_active": true
}
```
